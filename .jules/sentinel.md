## 2024-06-12 - [Hardcoded Secret Token in Nginx Config]
**Vulnerability:** A hardcoded token `xrpc-9f8e7d6c5b4a` was used in an `if` block within `server-php/config/conf.d/wordpress.conf` to bypass the default blockage of the `/xmlrpc.php` endpoint. This could allow unauthorized access to the XML-RPC endpoint, which is a known attack vector for brute force attacks and DDoS (pingback) attacks, if an attacker discovers this token through code disclosure or guessing.
**Learning:** Hardcoding secret tokens directly into infrastructure configuration files like Nginx is a security anti-pattern because configuration files are often tracked in version control, making the secret available to anyone with read access to the repository. The Nginx configuration language is not designed for robust authentication, and such manual checks often bypass standard, more robust authorization mechanisms.
**Prevention:** Remove all hardcoded authentication tokens from configuration files. Use standard authentication (like OAuth, API keys in headers, or JWTs) validated by the backend application or an API gateway, rather than raw string comparisons in the reverse proxy layer. If an endpoint is meant to be completely disabled, unconditionally block it (e.g., using `deny all;`) rather than leaving a secret backdoor.
