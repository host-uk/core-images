## 2024-03-11 - [Hardcoded Token Bypass for XML-RPC]
**Vulnerability:** A hardcoded token (`xrpc-9f8e7d6c5b4a`) was used in an Nginx configuration file (`server-php/config/conf.d/wordpress.conf`) to allow bypassing the XML-RPC block (`/xmlrpc.php`). By passing this token as a query parameter (`?token=xrpc-9f8e7d6c5b4a`), any user could bypass the restriction and access the potentially vulnerable XML-RPC endpoint.
**Learning:** Hardcoding secrets directly into Nginx configuration files creates a single point of failure that is stored in version control and easily discoverable by anyone with access to the codebase or configuration. It essentially creates a backdoor. This highlights a gap in reviewing configurations for embedded credentials.
**Prevention:** Avoid embedding hardcoded secrets, tokens, or credentials in configuration files. Security blocks should be unconditional (e.g., `deny all;`). If restricted access is genuinely required, use proper authentication mechanisms like HTTP Basic Auth managed via environment variables or rely on secure upstream services, never static string matching in server configurations.
