## 2024-05-03 - [Hardcoded Secret in Nginx Config]
**Vulnerability:** A hardcoded token `xrpc-9f8e7d6c5b4a` was found in `server-php/config/conf.d/wordpress.conf` allowing a bypass to the default XML-RPC blocking mechanism by visiting `/xmlrpc.php?token=YOUR_XMLRPC_TOKEN`. This exposes the application to brute force and reflection attacks if the token is discovered, which is likely since the configuration is in version control.
**Learning:** Hardcoded secrets in Nginx configuration files are risky. If a secret is hardcoded in source control, it's effectively compromised. Relying on an argument to bypass security controls in Nginx configurations can be dangerous if not securely managed, especially when the default action is to deny access.
**Prevention:** Avoid using hardcoded tokens in Nginx configuration files. If access must be restricted to specific endpoints, use robust authentication mechanisms or restrict by IP rather than relying on secret query parameters. If secrets are needed, they should be managed via secure environment variables or a dedicated secrets manager, though Nginx configurations often do not support runtime environment variable interpolation natively without specific tools like `envsubst`. For XML-RPC, unconditional blocking is usually the safest approach unless absolutely necessary for specific integrations, in which case IP whitelisting or upstream authentication should be used.
