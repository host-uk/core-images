## 2026-06-22 - [CRITICAL] Fix hardcoded secret in XML-RPC configuration
**Vulnerability:** A hardcoded token check `if ($arg_token = "xrpc-9f8e7d6c5b4a")` was present in the Nginx configuration `server-php/config/conf.d/wordpress.conf` which allowed bypassing the XML-RPC block to execute PHP scripts on the server.
**Learning:** Hardcoded authentication mechanisms in infrastructure components like reverse proxies are serious security risks because secrets cannot be easily rotated, are checked into version control, and any exposure grants permanent access. Access controls should be unconditionally enforced or rely on proper upstream authentication mechanisms instead of hardcoded tokens in proxy configurations.
**Prevention:** Unconditionally block sensitive or deprecated endpoints like `/xmlrpc.php` (`deny all;`) directly in Nginx, and strictly prohibit storing plaintext tokens or credentials in web server configuration files. Use automated configuration checks to flag `if ($arg_` or hardcoded tokens in `.conf` files.
