## 2024-04-13 - Hardcoded XML-RPC Bypass Token in Nginx Config
**Vulnerability:** A hardcoded secret token (`xrpc-9f8e7d6c5b4a`) was used in `server-php/config/conf.d/wordpress.conf` to bypass the XML-RPC block (`/xmlrpc.php`). This allowed any user who discovered or guessed the token to access the vulnerable XML-RPC endpoint, potentially leading to brute-force or DDoS attacks.
**Learning:** Hardcoded secrets in Nginx configuration files create permanent backdoors. While the intention was likely to provide administrative or programmatic access, embedding secrets directly into version-controlled configuration files exposes them to anyone with repository access and makes rotation difficult. The configuration explicitly checked `$arg_token = "xrpc-9f8e7d6c5b4a"`.
**Prevention:** Never hardcode secrets in configuration files. If an endpoint must be blocked by default but allowed for specific use cases, use robust upstream authentication mechanisms, IP-based allowlisting, or inject secrets securely at runtime via environment variables (though noting that this specific environment bypasses `envsubst`). For XML-RPC, which is a legacy WordPress feature, unconditional blocking (`deny all;`) is the most secure approach unless there is a strictly documented and managed business requirement.
